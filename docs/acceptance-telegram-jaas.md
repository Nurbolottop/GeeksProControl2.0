# Практическая проверка Telegram и JaaS на staging (этап 11B)

Staging: https://gpro.zeastudio.su (Basic Auth). Каждая проверка — **только после
разрешения владельца**. Реальные стажёры и группы 1.0 не участвуют.

## A. Telegram (@GeeksProAutoBot)

**Подготовка (владелец):**
1. В @BotFather: `/revoke` для @GeeksProAutoBot → новый токен (старый, если где-то светился, перестаёт работать).
2. Ввод токена на сервере — скрыто, в чат не присылать:
   `ssh -t root@72.56.116.115 'cd /opt/geekspro2 && python3 app/tools/set_telegram_token.py'`
3. Прислать в чат (это не секреты): свой Telegram User ID (@userinfobot), ID тестовой
   супергруппы проекта (−100…, темы включены, бот — админ с «Управление темами»),
   ID тестовой группы продаж (бот добавлен), ID «сотрудника продаж» (можно свой).

**Настройка (исполнитель, после разрешения):** в `/opt/geekspro2/.env` —
`TELEGRAM_TEST_CHAT_IDS=<свой id>`, `TELEGRAM_TEST_GROUP_IDS=<группа проекта>,<группа продаж>`,
`SALES_TELEGRAM_CHAT_ID=<группа продаж>`, `SALES_AGENT_TELEGRAM_IDS=<id>`,
`TELEGRAM_OUTBOUND_MODE=allowlist`; `… exec web python manage.py telegram_check`;
`scripts/gp2-compose.sh --prod up -d web celery` (перечитать env);
`scripts/gp2-compose.sh --prod --profile bot up -d bot` — **один** polling-процесс.

| # | Действие | Ожидание |
|---|---|---|
| 1 | `/start` | постоянная клавиатура «Начать стажировку / Я уже стажёр / Помощь», не исчезает |
| 2 | «Начать стажировку» → ФИО, телефон, Backend, Бишкек, «Подтвердить» | «ожидает подтверждения отдела продаж», меню «Статус заявки» |
| 3 | В группе продаж: `#оплата` + ФИО/Телефон/Направление/Город/Оплата | ответ «Принято»; бот присылает «зачислены», меню «Доступные проекты» |
| 4 | То же с городом «Ош» | «Данные не совпали — нужна сверка», не зачислено |
| 5 | Control → «Telegram-бот» → код → в группе проекта `/bind КОД` → «Подтвердить» | темы «Объявления» и направлений созданы один раз |
| 6 | Control: задача на себя → в боте «Мои задачи» → «В работу» → «Отправить работу» со скриншотом | сдача в карточке задачи, тимлиду — уведомление |
| 7 | Сообщение боту с другого (не allowlist) аккаунта | ответа нет; в журнале — `skipped` |
| 8 | `… stop bot` | polling остановлен |

Критерий: все 8 пунктов; в журнале «Telegram-бот» статус «Отправлено» только у тестовых чатов.

## B. JaaS (⛔ release-gate — пока анонимный вход не исключён практически)

**Подготовка (владелец):** аккаунт https://jaas.8x8.vc → AppID; «API Keys» → сгенерировать
пару, публичный ключ загружен, `kid` записан; приватный ключ — на сервер файлом
`/opt/geekspro2/secrets/jaas.pem` (`chmod 600`, через `scp`, не в чат); «Webhooks» →
endpoint `https://gpro.zeastudio.su/video/webhook/jaas/`, события PARTICIPANT_JOINED/LEFT,
ROOM_CREATED/DESTROYED; секрет вебхука — в `/opt/geekspro2/.env` редактором на сервере (`nano`), не в чат.

**Настройка:** `.env`: `VIDEO_PROVIDER=jaas`, `JAAS_APP_ID`, `JAAS_KEY_ID`,
`JAAS_PRIVATE_KEY_PATH=/app/secrets/jaas.pem`, `JAAS_WEBHOOK_SECRET`;
`… exec web python manage.py check` — без `gp2.E010/W011`.

| # | Действие | Ожидание |
|---|---|---|
| 1 | В консоли JaaS — требование токена; открыть `https://8x8.vc/<AppID>/test-room` без `?jwt` в чистом браузере | **вход невозможен** — только тогда `JAAS_ANONYMOUS_BLOCKED_VERIFIED=1` |
| 2 | Тимлид назначает собрание себе и тестовому участнику (с Telegram из A) | приглашение с кнопкой «Войти на собрание» |
| 3 | Кнопка в боте → одноразовая ссылка → вход | комната открыта с именем участника; повтор ссылки — 403 |
| 4 | Переслать приглашение другому аккаунту и нажать кнопку | отказ «только из Telegram участника» |
| 5 | Ведущий + участник в комнате, выход, повторный вход, второе устройство | события в карточке; «Подтверждено автоматически»; один человек, устройств 2 |
| 6 | Подменить подпись (curl с неверным `X-Jaas-Signature`) | 401 |
| 7 | Ручное исправление посещаемости с причиной | запись «Исправлено вручную», события провайдера не изменились |

Критерий: все 7 пунктов; при неуспехе п.1 — `VIDEO_PROVIDER=simulator` остаётся, видео
к эксплуатации не допускается.
