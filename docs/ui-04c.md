# UI-04C: завершение модуля стажёров и выпускников

## Выход выпускника из одного проекта
Заявка (бот `/leave` или руководитель со слов стажёра) с причиной → решение
руководителя. Только выпускнику с двумя активными проектами; новичок и
выпускник с одним проектом — заморозка или отмена. При одобрении условия
перепроверяются под блокировкой: закрывается участие только в выбранном
проекте («Вышел(а) из проекта по заявке»), незавершённые задачи этого
проекта — «К выполнению», второй проект и статус выпускника не меняются.

## Периоды стажировок
* Одобрение повторной стажировки — не начало: человек «Ожидает стажировки».
* Новый период открывается при фактическом вступлении в первый проект
  (дата вступления); следующие вступления периоды не дублируют.
* Заморозка/возвращение — тот же период; отчисление и отмена закрывают его.
* Выпуск записывается в период один раз (`Internship.graduated_on`).
* Сверка старых данных: `manage.py internship_reconciliation` (только отчёт).

## Подтверждение продаж
Граница интеграции — `apps.interns.sales.record_sales_confirmation(SalesEvent)`
для будущего Telegram-модуля. Принимаются только сотрудники из
`SALES_AGENT_TELEGRAM_IDS` (по умолчанию пусто), человек сверяется по телефону
и ФИО, каждое событие сохраняется (`SalesConfirmation`: источник, сотрудник,
время, результат), повтор события ничего не меняет. Кнопок подтверждения в
вебе нет — руководитель видит «Ожидает подтверждения отдела продаж» и решает
только после подтверждения.

## Сертификаты
В 2.0 и 1.0 механизма выдачи нет (только ссылка на кабинет geeks.kg в боте).
Добавлено хранение фактических данных: `InternshipCertificate` — один на
период стажировки; автоматически не создаётся. Нет данных — «Нет данных».
