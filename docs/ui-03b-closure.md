# UI-03B: документы, бриф, закрытый набор, закрытие проекта

## Закрытый набор
* Правило — `apps/teams/rules.recruitment_error`: новый участник направления
  вступает только в идущий проект с открытым набором. Кто уже активен в
  команде — работает дальше. ПМ и тимлидов назначает руководство — это не набор.
* Проверка на всех путях: формы руководителя и ПМ, карточка стажёра,
  правка участника (возврат вышедшего = вступление), анкета тимлида
  (`join_project_from_form`), публичная анкета по старой/новой ссылке
  (страница «набор закрыт», анкета не сохраняется), выпуск ссылки тимлидом.
  Telegram-бот участий не создаёт (только показывает
  `projects_open_for_recruitment`).
* Гонки и дубли: `lock_and_recheck` / `save_membership` — повторная проверка
  под `select_for_update` строки проекта; `set_recruitment` берёт ту же
  блокировку. Набор открывается только в идущем проекте; закрытие проекта
  набор закрывает.

## Документы (`apps/documents/project_documents.py`)
* Ровно четыре: бриф заказчика, договор, ТЗ, подписанный акт приёма-передачи.
* Права: руководитель — всё; назначенные (активные) ПМ и тимлид — смотреть,
  загружать, заменять, удалять; тимлид, который вёл закрытый проект, — только
  смотреть; остальные — 404 (views, сервис, `apps.common.media`, прямые ссылки).
* Закрытый проект: правка только руководителем и только с причиной
  («Исправление закрытого проекта» в истории и журнале).
* Замена — новая версия, прежняя в архиве с причиной «заменён»; удаление —
  архив «удалён». Файлы не удаляются. Имена файлов случайные
  (`documents/<проект>/<uuid>.<ext>`), исходное имя — в `original_name`.
* Вкладка 2.0 `documents/_project_tab.html` — у руководителя, ПМ и тимлида
  (у тимлида вкладка новая). Старые эндпоинты правки/«утверждения» на месте
  удалены: они меняли файл без истории.

## Бриф
* Общая ссылка `/brief/` сразу заводит проект и заказчика, бриф становится
  документом проекта, руководителю — уведомление со ссылкой на документы.
* Защита: поле-ловушка, лимит 5 отправок в час с адреса, одна отправка на
  браузер, повторный бриф (тот же телефон и проект за сутки) нового проекта
  не заводит. Публичные страницы — без внутренних данных; бриф по ссылке
  закрытого проекта не принимается. Кабинета заказчика нет.
* Страницы «Заказчики», «Заявки с брифа», «Документы» и публичный бриф — в 2.0.

## Закрытие (`apps/projects/closure.py`)
* Условия (и только они): три фиксации руководителя — разработка завершена,
  опубликован в production, принят заказчиком (дата, автор, история) — и
  четыре документа. Домен, GitHub, доступы, задачи, баги, прогресс — справочно.
* `close_project`: только руководитель, транзакция с блокировкой, повторная
  проверка, отказ при повторном закрытии, дата и автор, история, итог
  выпуска сохраняется в истории («Выпускники»), Telegram — после commit.
* «Завершён» нельзя поставить формой проекта, инлайн-формой, админкой и
  `update_project`; принудительное закрытие удалено; повторного открытия нет.

## Выпуск (`release_team`)
* Только активные участия этого проекта; повторный вызов ничего не делает.
* Активные новые стажёры — выпускники (основание — закрытое участие,
  `apps.dashboard.graduation`); свободным — «на проверке» и приглашение в бота.
* Уже выпускники статус сохраняют, у них закрывается только это участие.
* Замороженные: участие закрывается с причиной «Стажировка заморожена»,
  в выпуск не попадают. Вышедшие/отчисленные раньше — не выпускники.
  `internship_attempt > 1` — не доказательство.

## Заморозка (исправлено в UI-03C)
Заморозка сразу закрывает все активные участия — см. docs/ui-03c.md.
