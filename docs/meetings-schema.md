# Обязательные собрания: схема будущего модуля

**Правило 2.0.** На каждое активное направление каждого проекта — минимум одно
**проведённое обязательное** собрание за календарную неделю (пн–вс, Бишкек).
Тимлид может проводить дополнительные необязательные собрания. Обязательство
существует, даже если встречу не создали.

## Почему сейчас нельзя посчитать пропуски

`GroupMeeting` хранит только созданные встречи (тип, направление, дата, статус).
Признака «обязательное» нет. Поэтому:
- проведённая необязательная встреча неотличима от обязательной;
- если встречу вообще не создали, никакой записи нет — по табелю пропуск не виден.

Сейчас Dashboard показывает число **обязательств** (активные направления × проекты
за неделю), записи табеля (проведено / не проведено / не отмечено), а выполнение
обязательств — «Нет данных».

## Предлагаемая схема (миграция — по согласованию)

```
GroupMeeting  (существующая)
  + is_required   BooleanField(default=False)   # обязательное собрание недели
  + obligation    FK → MeetingObligation, null  # какое обязательство закрывает

MeetingObligation  (новая)
  project      FK Project
  direction    CharField(TeamRole: backend / frontend / mobile / uxui / qa)
  week_start   DateField (понедельник)
  status       open | fulfilled | missed | excused
  fulfilled_by FK GroupMeeting, null
  excused_by   FK User, null;  excuse_reason TextField
  created_at, closed_at
  unique (project, direction, week_start)
```

**Жизненный цикл.**
1. Celery по понедельникам 00:05 создаёт `MeetingObligation` на неделю — для каждого
   идущего проекта и каждого направления, где есть активный участник-стажёр.
2. Отметка «Проведено» у собрания с `is_required=True` переводит обязательство
   направления в `fulfilled`. Необязательные собрания его не закрывают.
3. В понедельник за прошедшую неделю незакрытые обязательства становятся `missed`.
   Это и есть «пропущенное обязательное собрание», даже без записи встречи.
4. Руководитель может отметить `excused` с причиной (праздник, заморозка проекта).

**Что это даст Dashboard и «Требует внимания».** Точное «пропущено обязательных»,
ссылки на конкретное направление проекта; позже — учёт посещаемости из видеопровайдера
(JaaS) в той же модели собрания.

Видеопровайдер и миграции на этом этапе не внедряются.

## Реализовано на этапе 9 (apps.video)

Схема выше не внедрялась: вместо `MeetingObligation`-записей обязанности
**вычисляются** по истории участий недели (`reports.weekly.members_during` —
та же основа, что у отчётов тимлидов 7B), поэтому прошлые недели считаются по
составу на ту неделю и ничего не нужно «создавать по понедельникам».

* `VideoMeeting` — обязательное / дополнительное собрание направления, встреча ПМ
  с тимлидами (не входит в норму). Время и статус — в Control.
* `MeetingParticipant` — приглашённый: секрет персональной ссылки и наш
  случайный `provider_user_id` (уходит в JWT как `context.user.id`).
* `ProviderEvent` — события видеосервиса как пришли (повтор — по idempotencyKey).
* `AttendanceCorrection` — ручные исправления (кто, кого, было → стало, причина).

### Видеопровайдер: JaaS (8x8) — что проверено по документации

| Возможность | Источник | Статус |
|---|---|---|
| JWT RS256, `kid` = AppID/ключ, `aud=jitsi`, `iss=chat`, `sub`, `room`, `context.user.id/name/moderator` | developer.8x8.com/jaas/docs/api-keys-jwt | реализовано, не проверено на живом аккаунте |
| Вебхуки PARTICIPANT_JOINED / LEFT, ROOM_CREATED / DESTROYED; `data.id` = userId из JWT | developer.8x8.com/jaas/docs/webhooks-payload | реализовано, не проверено на живом аккаунте |
| Подпись `X-Jaas-Signature: t=…,v1=…` (HMAC-SHA256, base64, только v1), повторы — idempotencyKey | developer.8x8.com/jaas/docs/webhooks-signatures | реализовано (окно 5 минут) |
| Запрет входа без JWT (анонимные гости) | в документации не найдено | **проверить в консоли JaaS** |

Пока вход без JWT не запрещён, анонимный участник придёт без нашего userId и
получит статус «личность не подтверждена» — посещение ему не засчитывается.
Персональная ссылка — bearer-ссылка: если её переслать, видеосервис не отличит
другого человека; одновременные подключения одного userId с разных устройств
помечаются «проверьте». Это ограничение провайдера, не устраняемое кодом.

Для подключения: аккаунт JaaS, AppID, загруженный публичный ключ (kid),
приватный ключ файлом (`JAAS_PRIVATE_KEY_PATH`), вебхук на
`/video/webhook/jaas/` и его секрет (`JAAS_WEBHOOK_SECRET`), `VIDEO_PROVIDER=jaas`.
