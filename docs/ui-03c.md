# UI-03C: заморозка по заявке и порталы ПМ / тимлида в 2.0

## Заморозка и возвращение (`apps/interns/freeze.py`)
1. Стажёр подаёт заявку с причиной в Telegram-боте (`/freeze`) — или
   руководитель оформляет её со слов стажёра на карточке.
2. Решает только руководитель: страница «Заморозки» (`/interns/freeze-requests/`).
   Пока заявка не одобрена, ничего не меняется.
3. Одобрение (атомарно, с блокировкой заявки, стажёра и строк участий):
   * все активные участия закрываются с причиной «Стажировка заморожена»
     (записи не удаляются);
   * незавершённые задачи стажёра в этих проектах («В работе», «На проверке»)
     возвращаются «К выполнению» (статус «Новая»); выполненные остаются;
     автор, исполнитель, комментарии и вложения не трогаются; в журнале —
     запись по каждой задаче;
   * статус — «Приостановлен», в журнале «Стажировка заморожена» с причиной;
   * места в командах освобождаются; закрытие бывшего проекта не выпускает.
4. Защита: повторное одобрение и повторная заморозка отклоняются; одна
   ожидающая заявка каждого вида (ограничение в БД); гонка с закрытием
   проекта — обе операции блокируют одни и те же строки участий.
5. Возвращение — отдельная заявка (`/return`). После одобрения стажёр
   «Ожидает стажировки» и сам выбирает проект в боте (`/projects`): только
   идущие проекты с открытым набором, по правилам новичков/выпускников и
   лимитам. Прежнее участие не восстанавливается, выбор — один раз.
   Направлению PM проект назначает руководитель. Оплата и продажи не нужны.
6. Сверка старых данных: `manage.py freeze_reconciliation` — отчёт;
   `--apply` закрывает участия замороженных датой заморозки из журнала.
   В dev-базе расхождений нет.

## Доступ тимлида
* Заморозками и возвращениями управляет руководитель — у тимлида кнопок нет.
* Карточка бывшего участника своего направления открывается для просмотра:
  участие с причиной выхода, оценки, задачи.
* Любые изменения в портале тимлида — только активному тимлиду проекта
  (`active_lead_project_or_404`): бывший тимлид видит историю, но не правит.

## Порталы ПМ и тимлида
Одна карточка 2.0 (`projects/card.html`, данные — `apps/projects/portal.py`):
* ПМ: обзор (путь проекта, сводка, готовность к закрытию — только просмотр),
  этапы и основной этап, команда и контакты, задачи, документы, отчёты,
  табель (просмотр), заказчик. Закрыть проект, открыть набор, подтвердить
  условия закрытия ПМ не может.
* Тимлид: обзор своего направления, команда своего направления и ссылка на
  анкету (при открытом наборе), задачи, табель (отметки и оценки), документы.
* Задачи (`apps/tasks/project_views.py`): руководитель — всё; ПМ — создать,
  править, сменить статус, удалить (в архив); тимлид — создать, править,
  сменить статус; закрытый проект — только просмотр.
* Перенесены в 2.0: карточка стажёра, форма участника, табель собрания,
  формы типа/ссылок/заказчика/резерва. Старые шаблоны порталов удалены.
  В 1.0-виде остаётся только «Моё резюме» тимлида (не проектная страница).
