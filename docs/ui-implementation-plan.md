## Ограничения

- Новый визуальный язык; старые CSS и разметку не переносим и не «освежаем».
- Views, сервисы, selectors, формы и URL сохраняются. Меняются шаблоны и, где нужно, контекст.
- **Новых зависимостей нет:** ни Python-пакетов, ни npm, ни сборщика. Остаются Django Templates, htmx и Alpine (уже лежат в `static/js`). Иконки — собственный SVG-спрайт из подмножества Lucide (ISC), один статический файл.
- Массовой переделки нет: модули переводятся по одному, каждый целиком.

## Архитектура

```
app/
  apps/ui/                       # новое приложение без моделей
    templatetags/ui.py           # компоненты: {% ui_button %}, {% ui_badge %}, {% ui_field %}, {% ui_card %}…{% end_ui_card %}
    navigation.py                # единое меню: пункты + роли, кому видны
    context_processors.py        # nav, тема, текущий раздел
    views.py                     # /ui/ — каталог компонентов (только staff)
  templates/
    layouts/app.html             # каркас приложения (сайдбар, топбар, контент)
    layouts/public.html          # публичные формы: бриф, анкеты, витрина кандидата
    layouts/auth.html            # вход, ошибки 403/404/500
    components/*.html            # разметка компонентов (шаблоны inclusion-тегов)
    <модуль>/…                   # страницы модулей на новом каркасе
  static/gp2/
    tokens.css  base.css  layout.css  utilities.css
    components/*.css
    icons.svg                    # SVG-спрайт
    app.js                       # тема, drawer, тосты, htmx-хуки (~150 строк)
```

**Один каркас на все роли.** Вместо трёх `base.html` — `layouts/app.html` с меню из
`navigation.py`. Порталы PM и тимлида становятся разделами того же приложения с
меню своей роли. Это убирает дублирование и сразу даёт адаптивность всем ролям.

**Компоненты как теги шаблонов.** Inclusion- и block-теги в `apps/ui`:
вызов `{% ui_button "Сохранить" variant="primary" %}` всегда даёт одинаковую разметку и классы.
Слоты (`{% ui_card title="…" %}…{% end_ui_card %}`) — небольшой собственный block-тег,
без django-cotton и подобных пакетов.

**Формы.** `{% ui_field form.email %}` и `{% ui_form form %}` рендерят любые Django-поля
в разметке дизайн-системы: label, подсказка, ошибка, required, состояния. Формы в views не меняются.

**Таблицы.** DataTable на сервере. Сортировка, фильтры и пагинация — через
`hx-get` + `hx-push-url`, обновляется только тело таблицы. На ширине < 768px строки
показываются как карточки (CSS + `data-label`), без отдельного мобильного шаблона.

**Тема.** Короткий inline-скрипт в `<head>` ставит `data-theme` до отрисовки (без мигания),
выбор хранится в `localStorage`, по умолчанию — системная тема. Позже — в профиле пользователя.

**Сосуществование.** Пока модуль не переведён, он живёт на старом `base.html`
со старым CSS. Новые страницы старый CSS не подключают. 2.0 ещё не в
production, поэтому флаги и параллельные URL не нужны.

## Качество

- **Тесты:** smoke-тест каждой переведённой страницы для каждой роли (200 / 403 как раньше);
  тест, что новые страницы не подключают старый CSS; существующие 912 тестов зелёные.
- **Адаптивность:** проверка в браузере на 360, 768, 1280, 1440px; без горизонтального скролла;
  цели касания ≥ 44px.
- **Доступность:** контраст ≥ 4.5:1, видимый фокус, клавиатура, `aria-*` у htmx-обновлений
  (`aria-live` для тостов и таблиц), `prefers-reduced-motion`.
- **Бюджет:** CSS дизайн-системы < 60 КБ, JS только htmx + Alpine + `app.js`.
  Шрифт Inter (сейчас 352 КБ) — сократить до латиницы и кириллицы (~100 КБ).
