# Dashboard руководителя: показатели и источники данных

Код: `app/apps/dashboard/metrics.py` (расчёты), `selectors.py` («Требует внимания»,
очереди решений), `views.py`. Шаблоны только выводят готовые значения.
Если значение нельзя посчитать — показывается «Нет данных», а не 0.

## Общие определения

| Понятие | Определение |
|---|---|
| Стажёр | карточка `Intern` не в архиве и не тимлид (`teams.selectors.staff_intern_ids`); ПМ считаются стажёрами — как в недельном отчёте 1.0 |
| Активный стажёр | `Intern.status = active`. Считаются **люди**: участие в нескольких проектах число не увеличивает |
| Выпускник | только достоверные события (`apps/dashboard/graduation.py`): был активен в момент **официального** завершения проекта и не заморожен на эту дату (по журналу) **или** сохранённая отметка выпуска (`graduate_status`) **или** повышение до штатного тимлида. Повторная стажировка (`internship_attempt > 1`) выпуском **не** считается. Неоднозначные записи не считаются и выводятся командой `manage.py graduate_reconciliation` (только чтение) |
| Новый / старый стажёр | активный не выпускник / активный выпускник |
| Филиал | `branch_of(intern)` — поле «Филиал», при пустом — по городу |
| Основной этап проекта | `Project.primary_stage` — выбирают вручную руководитель или ПМ проекта, сам не меняется. Если не выбран — подсказка по `current_stage` с пометкой «не подтверждено» |
| Неделя | понедельник–воскресенье, время `Asia/Bishkek`. По умолчанию — последняя полностью завершённая; текущая помечается «неполная» |

## KPI

| Показатель | Источник |
|---|---|
| Активные стажёры | число людей со статусом «Активный»; подпись — число их активных участий в проектах (`TeamMember`) |
| Новые / Старые стажёры | активные без / с признаком выпускника |
| Выпускники | все люди с подтверждённым выпуском, включая повышенных до тимлида, в любом текущем статусе; записи на сверку не учитываются |
| Всего / Активные / Завершённые проекты | `Project` не в архиве: все / статус «Активный» / статус «Завершён» (подпись: приостановлено, прекращено) |

## Проекты по этапам

| Категория | Этапы `current_stage` |
|---|---|
| Новый | Новый, Документы, ТЗ, Формирование команды |
| Активная разработка | Дизайн, Backend, Frontend, Мобильная разработка |
| Staging / тестирование | Тестовый сервер, Тестирование, Доработка |
| Передача заказчику | Сдача, Продакшен |
| Завершён | статус проекта «Завершён» (или этап «Завершён») |

Проекты со статусом «Отменён» / «Клиент отказался» в распределение не входят и показаны
отдельной строкой. «Новые проекты» — это основной этап «Новый», а не дата создания.

## Неделя (события по датам)

| Показатель | Источник |
|---|---|
| Зарегистрировано новых стажёров | `Intern.created_at` в пределах недели (по времени Бишкека) |
| Получили статус выпускника | дата **первого** датированного основания: закрытие проекта, в котором человек был активен, или повышение до тимлида |
| Заморозки | журнал аудита: «Стажировка заморожена» и (с UI-02) «Статус изменён → Приостановлен» из формы карточки |
| Добровольные отмены | `TeamMember.left_reason = «Сам ушёл»`, `left_at` в неделе — уникальные люди |
| Отчисления | `left_reason` «Не подошёл» / «Не отвечает», `left_at` в неделе — уникальные люди |
| Завершено проектов | `Project.actual_end_date` в неделе, статус «Завершён» |
| Обязательные собрания | обязательства: активные направления × идущие проекты за неделю; выполнение — «Нет данных» (нет признака обязательности, см. [meetings-schema.md](meetings-schema.md)). Отдельно — записи табеля: проведено / не проведено / не отмечено |
| Отчёты ПМ | обязательство: ПМ, у которого в неделе шёл хотя бы один проект — **один отчёт в неделю на ПМ**, не на проект. Сдано в срок — `ProjectReport` автора в пятницу или субботу; «в другой день» — отдельно; «не сдано» — после субботы |
| Отчёты тимлидов | обязательство: по одному на каждую пару «тимлид × закреплённый активный проект». **Сданных посчитать нельзя** — в системе нет механизма сдачи отчёта тимлидом |

## Сравнение недель

- События (верхние строки) считаются по датам событий для любой недели.
- Численность «на конец недели» берётся **только** из снимка `WeeklyReport.data['dashboard_state']`,
  который с UI-02 пишет еженедельная задача (понедельник 06:30 за прошедшую неделю). Для недель
  без снимка — «Нет данных». Активные стажёры и активные проекты читаются и из снимков 1.0
  (те же определения).
- Процент изменения не показывается, если база равна 0.

## Требует внимания

Проект без ПМ, проект без тимлида, прошедший дедлайн, проект на передаче без обязательных
документов, пропущенное или не отмеченное собрание за 14 дней, ПМ без отчёта за прошлую неделю,
очереди решений (заявки с брифа, банк резюме, выпускники «на проверке», ждут проект), выпускник
«на проверке» дольше 14 дней. Каждый пункт ведёт на объект. Статус «Проблемный» не используется.

## Чего не хватает в данных (нужно решение)

| Показатель | Почему нельзя точно | Предложение |
|---|---|---|
| Сданные отчёты тимлидов | механизма сдачи нет | модель `LeadWeeklyReport(project, lead, week_start, text, submitted_at)` + форма в портале тимлида — **миграция** |
| «Обязательные» собрания | признака обязательности нет; сейчас считаются все собрания табеля, кроме «Другое» | поле `GroupMeeting.is_required` или норма собраний на группу в неделю — **миграция** |
| Численность за прошедшие недели | снимков нет до первого понедельника после UI-02 | накапливается автоматически, без миграции |
| Заморозки до UI-02 через форму | смена статуса в форме не логировалась | с UI-02 логируется; опционально — отдельная история статусов `InternStatusChange` (миграция) |
