# UI-04B: предупреждения, отчисление, отмена, повторная стажировка

## Направление PM
Правила состава одинаковы для всех направлений, включая PM: новичок — 1 активный
проект, выпускник — 2, в направлении проекта не больше 4 выпускников (4 новичка —
ориентир). Стажёр PM сам проект не выбирает: ни бот, ни ссылка анкеты, ни ПМ —
только руководитель (`teams:pm_add` проверяет правила под блокировкой).
Seed больше не создаёт новичка в двух проектах. Исторические нарушения:
`manage.py membership_rule_audit` (только отчёт).

## Предупреждения (`apps/interns/discipline.py`)
* Выдаёт тимлид (активный, своё направление, свой проект) или руководитель;
  причина, автор, дата, период стажировки.
* 3 активных предупреждения периода → `DisciplineCase` руководителю (одно
  ожидающее на человека — ограничение БД). Это не отчисление.
* «Оставить» — предупреждения «Учтено», счётчик 0, следующие три — новое дело.
* «Отчислить» — участия закрыты («Отчислен»), незавершённые задачи «К выполнению»,
  вход ПМ-стажёра закрыт, период закрыт, статус «Отчислен», выпуск не присваивается.

## Добровольная отмена
Заявка (или руководитель на карточке) → решение руководителя: то же завершение
участий, период «Отмена — ушёл(ла) самостоятельно», статус «Отмена». Не отчисление
и не заморозка; в Dashboard — «Добровольные отмены», отдельно от отчислений.

## Повторная стажировка
Только после отчисления/отмены, тот же профиль: заявка → подтверждение продаж
(номер оплаты) → одобрение руководителя → новый период, предупреждения с нуля.
Анкета и бот сами не зачисляют. Отдельной роли «продажи» пока нет —
подтверждают руководитель/администратор (`discipline.confirm_sales`); Telegram-
сценарий продаж подключится к этой же функции. Возвращение после заморозки не
меняется: без оплаты и без нового периода.
