# Требования к интерфейсу Telegram-бота (для отдельной Telegram-задачи)

Зафиксировано на этапе 6; в этапе 6 бот не переписывался.

* Постоянные нижние кнопки — `ReplyKeyboardMarkup(is_persistent=True,
  resize_keyboard=True, one_time_keyboard=False)`; клавиатура остаётся после
  любых сообщений бота.
* Набор кнопок зависит от роли и статуса пользователя (стажёр, выпускник,
  замороженный, ожидающий проект, тимлид, сотрудник продаж и т. д.).
* У каждой кнопки — рабочий обработчик; кнопок без действия нет.
* Контекстные подтверждения (выбор проекта, «да/нет») — inline-кнопки.
* Уже готовые серверные точки, к которым бот подключается без дублирования
  логики: заявки `apps.interns.freeze` (/freeze, /return), выход из проекта
  `apps.interns.discipline.request_leave` (/leave), выбор проекта после
  возвращения `freeze.choose_project` (/projects), подтверждение продаж
  `apps.interns.sales.record_sales_confirmation`.
* Все исходящие сообщения — только через `apps.common.outbound` / защиту
  `apps.common.telegram_guard` (режимы off / allowlist / on).

## Задачи и проверка работ (этап 7, подключить на этапе 8)

Backend готов, бот не изменялся и не запускался:

* `apps.tasks.workflow.intern_tasks(intern)` — назначенные стажёру задачи
  активных проектов (кнопка «Мои задачи»).
* `workflow.start_work(task_id, intern)` — «Взять в работу».
* `workflow.submit_from_telegram(chat_id, task_id, screenshot=…, links=…, comment=…)`
  — сдача: исполнитель определяется по подтверждённому `telegram_chat_id`,
  скриншот обязателен, ссылки — только http/https, повторная сдача до
  проверки отклоняется. Результат — «На проверке».
* Статус проверки — `TaskSubmission.outcome` (на проверке / принято /
  возвращено с причиной `review_comment`); история — `TaskEvent`.
* Уведомления стажёру — только разрешённые и только через
  `apps.common.outbound` / `telegram_guard`; в этапе 7 реальные сообщения
  не отправляются.
* Клавиатура — постоянная `ReplyKeyboardMarkup(is_persistent=True,
  resize_keyboard=True, one_time_keyboard=False)`, набор кнопок по роли и
  статусу, у каждой кнопки рабочий обработчик; подтверждения — inline.

## Этап 8: что реализовано (apps.tgbot)

* Запуск: `manage.py run_telegram_bot` (long polling → `apps.tgbot.dispatcher.handle_update`).
  Запускается только по отдельному решению; с одним токеном — не вместе с
  `run_graduate_bot`. Вне production входящие — только из allowlist.
* Постоянное меню — `ReplyKeyboardMarkup(is_persistent=True, resize_keyboard=True,
  one_time_keyboard=False)` в каждом ответе; набор кнопок — `apps.tgbot.menus`.
* Состояние диалога — `DialogState` (БД), повторы update — `TelegramUpdate`.
* Исходящие — очередь `OutboundMessage` → `GuardedTeleBot`; Celery `flush_outbox`.

### Шаблон сообщения отдела продаж (единственный принимаемый)

```
#оплата
ФИО: Асанов Бакыт Маратович
Телефон: +996 700 123 456
Направление: Backend
Город: Бишкек
Оплата: 12345
```

Принимается только из `SALES_TELEGRAM_CHAT_ID`, от `SALES_AGENT_TELEGRAM_IDS`,
не пересланное. Город — Бишкек или Ош. Несовпадение телефона, ФИО, направления
или города и неоднозначность — на сверку (Control → «Telegram-бот»).

### Привязка проектной группы (руководитель, вручную)

1. Создать в Telegram супергруппу проекта, включить «Темы».
2. Добавить бота администратором с правом «Управление темами».
3. Control → «Telegram-бот» → «Привязать группу» → выпустить код (30 минут).
4. В группе отправить `/bind КОД`.
5. В Control проверить название и chat_id → «Подтвердить». Бот создаст темы:
   «Объявления» и по направлениям проекта (Backend, Frontend, Design, Mobile,
   QA, PM, другие). «Обновить темы» — досоздаёт новые и удалённые.
6. Служебные группы «Все тимлиды» и «Все ПМ» — так же, видом группы.
   Группа продаж — настройкой `SALES_TELEGRAM_CHAT_ID`.

Для stage группа должна быть в `TELEGRAM_TEST_GROUP_IDS`, режим — `allowlist`.
Для фактов вступления бот получает `chat_member` (бот — администратор).

## Обязательная проверка этапа 10 (до реального старта бота)

Решение: в Control 2.0 — **один** Telegram-бот (`apps.tgbot`, `run_telegram_bot`).
До запуска:
1. Перенести сценарий выпускника из `run_graduate_bot` (правила, «Продолжить /
   Закончить стажировку», банк резюме) в `apps.tgbot`, используя существующие
   `apps.graduate_bot.services`, без второй системы регистрации.
2. Отключить конкурирующий запуск `run_graduate_bot` в конфигурации 2.0
   (два polling-процесса с одним токеном запрещены).
3. Постоянная нижняя клавиатура — без изменений.
